# CLAUDE.md

## What this is

PJM energy-market analytics suite: a parquet data lake, a `pjm_core` engine library, a CLI orchestrator, and a Streamlit app with ~25 screens. Covers all 12 PJM trading hubs (primary: Dominion Hub). Sibling of `../ercot-suite` — same design, no shared code.

## Quick reference

```bash
# Setup
./setup.sh                # venv + config scaffold + initial data pull
./setup.sh --no-data      # venv only

# Run the app
./launch_portal.sh        # http://localhost:8510
./launch_portal.sh 8511   # custom port

# Data updates (run from PJM_Data_Hub/)
.venv/bin/python orchestrate.py update all
.venv/bin/python orchestrate.py status
```

## Dev environment

- Key deps: `pandas`, `pyarrow`, `streamlit`, `plotly`, `gridstatus`, `numpy`, `requests`, `yfinance`, `openpyxl`, `curl_cffi` (browser-TLS client for the ICE forward-curve pull)

## Conventions

- **Timezone**: All timestamps are naive Eastern Prevailing Time (US/Eastern). Use `pjm_core.tz.localize_eastern()` when tz-aware math is needed. Consequence: on the November DST fall-back day the 01:00 hour repeats under one label, so the hourly stores hold 720 hours for November, not 721 — hub and zone prices both drop it. Anything that needs that hour must carry `datetime_beginning_utc` from the PJM feed, which no store currently keeps.
- **Interval size**: Hourly (unlike ERCOT's 15-min). `settlement.INTERVAL_HOURS = 1.0`.
- **LMP components**: `total_lmp = energy + congestion + loss`. Always keep all three.
- **Credentials**: `PJM_Data_Hub/config.json` (git-ignored, chmod 600). Keys: `subscription_key` (PJM Data Miner 2), `eia_api_key` (EIA gas strip). Access via `pjm_core.credentials`.
- **Paths**: All data paths go through `pjm_core.paths` — never hardcode `data/` paths.
- **Screens**: Numbered `NN_Name.py` in `app/screens/`. Sidebar order and grouping are **not** the filename prefix — they're defined explicitly by the `st.navigation({...})` dict in `app/Home.py`, keyed by section ("Start Here", "Explore", "Capacity & Peaks", "Analyze"). Each page's URL slug also comes from its `st.Page(..., title=...)` there.
- **Data lake**: Parquet files under `PJM_Data_Hub/data/` with `.last_update.json` freshness markers.
- **Gas strip vintages**: every `gas_strip.update()` pull is also archived to `data/gas/henry_hub_strip_history.parquet` (one snapshot per day, keyed by `asof`). `gas_strip.strip_asof(date)` returns the strip as it stood on a date; `price_forecast.run(asof=d, gas_asof=d)` re-runs the forecast from that vintage (Price Forecast screen → "Gas strip vintage" picker). A missing vintage raises — never silently substitute today's strip in a backtest. `python -m pjm_core.gas_strip backfill --days=365` reconstructs vintages from Yahoo per-contract history; note Yahoo delists expired contracts, so reconstructed vintages older than a few days are missing their near months (front year comes from `_extend_to_horizon`'s mean-reversion fallback).
- **Gas anchor**: the forecast anchors on `gas_strip.strip_median()` — the per-contract median of the last 5 vintages, not a single day's settle — which rejects bad ticks from the unofficial Yahoo feed. Keep the window short: a forward is near-martingale, so averaging over weeks lags real moves rather than smoothing noise. `anchor_vintages=1` gives the raw settle.
- **Gas volatility**: seasonal in the *delivery* month (a January contract carries ~2x a July one) and mean-reverting in horizon (`_gas_terminal_sigma`, OU with κ = 0.29/yr), not a flat σ·√t. Seasonality scales only the final `DELIVERY_WINDOW_YEARS` of variance — multiplying the whole accumulated path puts σ ≈ 1.2 on a far-out January, which implies a P50 at half the forward. Constants are fitted to EIA Henry Hub spot; `gas_strip.forward_vol()` supersedes them per-contract once ~30 vintages exist.
- **Gas → power pass-through**: modelled as a structural elasticity (`GAS_PASS_THROUGH_BETA = 0.90`, measured on DOM Hub), *not* a correlation between the gas and heat-rate shocks — a fixed correlation lets the implied β drift with the ratio of the two σ's. A plain product of independent lognormals implies β = 1.0 and overstates the band.
- **Cross-month correlation**: gas is drawn as one OU-correlated path across the horizon, so `run()` also returns `strip_p10/p50/p90` — the distribution of the *horizon-average* price. Use those for annual/PPA-level numbers; don't derive them from the monthly bands. Averaging the monthly P10/P90s assumes lockstep months and runs too wide; independent monthly draws diversify the regime risk away and run far too narrow (on the current 18-month strip: 50 / 38 / 15 $/MWh of spread respectively).
- **Heat rate**: one pooled fit of `log(HR)` on a linear trend, calendar-month effects, and extreme-weather anomalies, across every month of history (`_fit_heat_rate_model`). Falls back to the old per-calendar-month recency median (3-year half-life, `HR_RECENCY_HALFLIFE_YEARS`) below `HR_MODEL_MIN_MONTHS = 36`; `run()` reports which via the `hr_source` column. Why pooled: DOM Hub implied HR trends **+7.5%/yr** (t=5.8) on coal retirement and Dominion-zone data-centre load, and a median of a recency-weighted window *lags* a drift instead of extrapolating it — worth ~+20 $/MWh of one-sided under-forecast. Pooling estimates the trend off ~80 months rather than the ~6 in one calendar bucket. The trend is held flat past `HR_TREND_MAX_YEARS = 2` beyond the fitted data, or a linear fit compounds out to nonsense.
- **Heat-rate weather channel**: *extreme-day degree sums* (`xcold` = Σ max(35°F − daily mean, 0), `xhot` = Σ max(daily mean − 80°F, 0), DOM zone), not monthly HDD/CDD totals — scarcity is made on the few stretched days and a monthly total averages them away. On totals, CDD is insignificant (t=0.8); on extreme-day sums both terms carry (t=2.8 cold, 1.9 hot) with lower residual σ. Weather anomalies are unknowable ahead, so the point forecast sets them to zero and their variance moves into σ — which is what makes σ seasonal. σ also carries parameter uncertainty `x'(X'X)⁻¹x·s²`, without which the near-in bands are badly overconfident. Two things deliberately **not** in the model: a trend×season interaction (peak months do trend faster in-sample, but it lost out-of-sample at every horizon — overfitting), and a load term (load anomaly is 0.56 correlated with weather anomaly and adds nothing beyond it, residual corr −0.004).
- **Backward gaps in the gas curve**: a reconstructed vintage has no *near* months — Yahoo delists expired contracts, so a vintage stamped 2025-07-29 can start at 2026-08 — which means the months a backtest scores are exactly the months `_extend_to_horizon` invents. It fills in both directions: forward gaps mean-revert from the last contract, backward gaps from `spot` (the most recent realised Henry Hub print before the as-of, passed down from `run()`'s already-truncated `gas_history`, so no lookahead), and both re-apply `_price_seasonal_shape` — the curve's *own* level seasonality, measured off a centred 12-month rolling mean, distinct from the volatility `_seasonal_shape`. Before this, `max(k, 0)` clamped every backward gap to "zero months past the end" and returned the most deferred contract's price for all 12 months: a 2025-08 slot filled with January-2029 gas, dead flat. Fixing it took the filled curve from bias +1.09 / MAE 1.57 / MAPE 47% to bias +0.05 / MAE 0.71 / MAPE 18%. Live forecasts never hit this path — the liquid strip runs 23 months against a 12-month horizon.
- **Regional gas basis** (`datasets/gas_basis/`, `orchestrate.py update gas_basis`): EIA "gas sold to electric power consumers" by state (`N3045<ST>3`, $/Mcf → $/MMBtu), 8 PJM states, vs Henry Hub. **Built, measured, and left off by default** — `price_forecast.USE_DELIVERED_GAS = False`, `run(use_basis=True)` to enable. The signal is real: DOM Hub burns Mid-Atlantic gas, and Feb 2026 settled $3.62 Henry Hub against $7.09 delivered to Virginia, which is why that month shows an implied heat rate of 24.1 vs a normal 12.3 on the gas actually burned. But it does not pay for itself in a *forecast*: walk-forward over 138 (month, horizon) pairs scored only on published-basis months gives MAE 7.67 on Henry Hub, **6.86 with perfect basis foresight**, and **8.44 with the basis a forecaster can actually have** (the seasonal mean). Winter inverts hardest, 9.99 → 14.33. Splitting out a term you cannot forecast turns it into a multiplicative error the heat rate then scales by ~10. Conditioning basis on cold-day anomalies (corr +0.48 in winter, t=2.3) trims the winter anomaly σ only 1.00 → 0.90, and the weather is not known ahead either. Fit window is `BASIS_HISTORY_YEARS = 10`: Marcellus reset this market (VA basis averaged ~$1.0–1.6 through 2011, ~$0.4–0.7 since 2012), though note the excluded window holds the largest print on record (Jan 2014, +$12.50). What would flip the verdict is a **daily traded-hub feed** (Platts/Argus Transco Z5, TETCO M3) — it supplies a forward basis *quote* instead of a seasonal mean, and drops the monthly averaging, the ~3-month publication lag, and the gaps (EIA has no Jan-2026 Virginia print, the single most important month in the sample).
- **Validating one side of the model**: `--hr-only` and `--gas-only` score the heat-rate estimators (Henry Hub, pooled, pooled+basis) and the filled gas curve separately; the headline backtest mixes them and their errors partly cancel, so a real improvement to one side can make the end-to-end MAE *worse*. That is not hypothetical — the pooled heat-rate model moved the headline from bias −7.87/MAE 15.40 to +3.21/19.82 while improving heat-rate MAE 15.4 → 10.0 against realised gas. `--hr-only` grants perfect gas foresight and `--gas-only` ignores power entirely, so both compare components rather than scoring the forecast. They stop being necessary once real-strip rows accumulate.
- **Forecast accuracy**: `pjm_core.forecast_backtest` walk-forwards the model across every archived vintage — monkey-patches `_load_dom_hub_monthly`/`_gas_from_eia` per as-of to prevent lookahead, then compares each forecast month's P50/P10/P90 to the realised LMP. `gas_from_strip` marks per row whether the forecast month's own gas contract was in the vintage (True) or filled by mean-reversion (False). Today that flag is False on every row (Yahoo delists expired contracts, so reconstructed vintages start beyond the realised window); it will start populating a few months out as live daily pulls line up with realised months. Only *finished* months are scored (`MONTH_COMPLETE_FRAC = 0.98` of the calendar month's hours) — the hub store grows through the current month, so without the guard a 20-day August gets averaged and scored as that month's clearing price. The threshold is stricter than the zone-price ETL's 0.90 and still clears DST (March 743/744, November 720/720). Persists to `data/price_forecast/backtest_results.parquet`; refreshed by the Forecast Accuracy screen (Analyze section) or `python -m pjm_core.forecast_backtest --horizon=12`.
- **Backtest truncation is per-series, and cuts at the month boundary plus a publication lag** (`forecast_backtest._seen_before`): every history the backtest feeds the model — hub LMP, Henry Hub spot, weather, basis — is a *monthly average*, knowable neither before the month ends nor before the agency releases it. Two cuts, both of which were missing. **(1) The month boundary.** The old `month < asof` mask admitted the as-of's own month for any as-of stamped after the 1st. On as-of 2026-01-02 that leaked January's realised **$7.72** Henry Hub, published in February; `run()` passes the last spot print down as `_extend_to_horizon`'s `spot` anchor, and with `REVERSION_MONTHS = 24` decaying a shock only ~19% over five months, the spike propagated across every backward-gap month. That vintage forecast Mar-2026 at a P50 of **$76 against a $30 actual** — the worst row in the set (z = -2.49) — and its four next-worst rows were Apr-Jun from the same fill. **(2) The publication lag.** `GAS_PUBLISH_DAY = 7` (EIA's monthly RNGWHHD rollup lands in the first week of M+1) and `BASIS_LAG_MONTHS = 3` (N3045<ST>3, only reachable with `USE_DELIVERED_GAS` on or via `--hr-only`). LMP and weather keep a zero lag — Data Miner posts RT LMP next-day and temperatures are observed daily. The gas lag is expressed as a release *day*, not a whole month, because a forecaster on the 2nd genuinely lacks last month's average while one on the 15th has it; month-granular arithmetic cannot say that. It is not decorative: `_monthly_asofs` takes the earliest vintage per calendar month, so **11 of 12 as-ofs fall before the 7th** and every one was being handed a figure that did not yet exist. Together the two cuts took the 2026-01-02 vintage's gas-fill MAE 2.30 -> 0.50 and its price MAE 23.3 -> 11.6.
- **Removing a leak can move the headline either way — judge a gas-side change on `--gas-only`, not the headline.** The gas curve alone improved monotonically as the cheats came out: bias +0.047 / MAE 0.715 / MAPE 17.7% (leaky) -> -0.01 / 0.68 / 16.6% (month boundary) -> **-0.03 / 0.64 / 15.3%** (plus publish day). The headline wandered — -10.37 / 17.14 / cov 87% -> -11.03 / 17.50 / 85% -> **-11.29 / 17.11 / 83%** — because the model's price bias is negative, so anything that biases gas *high* flatters it by cancellation. Not hypothetical: a two-sided fill (interpolating backward gaps between `spot` and the first traded contract instead of reverting to $4) was built and **rejected** on exactly this. It improved the headline 17.50 -> 15.36 while making the gas curve *worse*, 0.68 -> 0.75, by dragging fills up toward contango'd deferred contracts. Its per-vintage delta tracks gap length — wins at gaps <=8 months, loses at >=9 — and the long-gap vintages carry 50 of the 78 rows. Gating on a gap threshold would be fitting a cutoff to 12 observations, and live forecasts never reach this path anyway (the liquid strip runs 23 months against a 12-month horizon). An OU bridge (conditional mean given both endpoints) was also tried and is near-identical to linear here: a 24-month e-folding barely reverts across a 14-month gap.
- **Band calibration is a location problem in winter, not a width problem**: backing sigma out of each row's band (`sigma = ln(P90/P50)/1.2816`) and scoring `z = ln(actual/P50)/sigma` gives shoulder -0.23 +/- 0.70, summer +0.33 +/- 0.56, winter **+1.12 +/- 0.41**. Winter's spread is the *tightest* of the three — the misses are stacked on one side, not scattered — so widening winter sigma would be treating a bias as variance. If anything the other 9 months run ~30% too wide (94% / 100% coverage on an 80% band). But the winter cell is 3 distinct months x ~6 near-perfectly-correlated horizons: effective n is **3**, one gas miss (Jan-2026, strip $4.25 vs realised $7.72 — the heat-rate model was near-exact, 16.07 vs 16.35 realised) and one delivered-gas basis event (Feb-2026). Don't tune on it.
- **The pooled heat-rate model is not drifting** — checked because Jul-2026 printed an implied HR of 28.6 against a forecast 20.8. Log-HR residuals: full sample 0.000 +/- 0.183, last 24m -0.008, last 12m +0.004, last 6m +0.060 (t = 0.67). Mean-zero by season too across 6.5 years (winter / summer / shoulder all 0.000, sd 0.183-0.193), `corr(resid, fitted level) = 0.00`, mild positive skew 0.39. Jul-2026's +0.319 residual is the 7th-largest of 79 months — ordinary. No action: the trend is not under-extrapolating.
- **Primary hub**: `DOMINION HUB` — defined in `pjm_core.settlement_points.PRIMARY_HUB`.
- **Zone names differ by feed**: the metered-load feed uses short codes (`PEP`, `CE`, `BC`, `PL`…), the LMP feed uses long names (`PEPCO`, `COMED`, `BGE`, `PPL`…). Cross them with `settlement_points.LOAD_ZONE_PRICE_ZONE` (20 of 22 load zones). `RTO` and `OVEC` are deliberately absent — no zonal LMP exists for either.
- **Never default a zone to a hub price**: only 6 of 22 load zones have a namesake trading hub, so `ZONE_HOME_HUB.get(zone, PRIMARY_HUB)` silently paired e.g. PEPCO load with a Virginia price. For a zone's price at a specific hour use `pjm_zone_prices.load_hourly(market="RT", zones=[...])`; fall back to a hub only where no zonal LMP exists, and label it as a reference.
- **Zone prices are two stores**: `pjm_zone_lmp_hourly.parquet` (hour × zone × market) and the `pjm_zone_lmp_monthly.parquet` average derived from it. `update()` re-fetches a month when *either* store lacks it; hourly completeness is judged on distinct-hour count (`HOURLY_COMPLETE_FRAC`), not row presence, so an interrupted backfill resumes instead of being marked done.
- **Settlement math**: Offtaker-signed (positive = offtaker receives). See `pjm_core/settlement.py`.

## Common tasks

- **Add a new screen**: Create `app/screens/NN_Name.py` (import shared helpers from `app._common`), then register it in the `st.navigation({...})` dict in `app/Home.py` under the right section — a screen file that isn't listed there won't appear.
- **External market data with no free API**: some sources are Akamai-gated (CME, ICE product pages). The pattern is a user-maintainable CSV seed plus a best-effort scraper that never raises and falls back to the CSV — see `pjm_core/futures.py` (ICE free ~15-min-delayed forward curve via `curl_cffi`) and `pjm_core/capacity.py` (RPM reference table).
- **Add a new dataset**: Create a module under `datasets/`, add its update function to `orchestrate.py`, register data paths in `pjm_core/paths.py`.
- **Modify engine logic**: Edit the relevant module in `pjm_core/`. Multiple screens may depend on it — check callers.
- **Check forecast quality**: `python -m pjm_core.forecast_backtest --horizon=12` (prints headline stats + caches to parquet) or open the Forecast Accuracy screen. The `real_strip_only=True` split only populates once live daily pulls line up with realised months — before then, the reported bias/MAE bundles model error with strip-extrapolation error and the screen banner says so.
